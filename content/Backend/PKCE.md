# **What is PKCE?**

**PKCE (Proof Key for Code Exchange)** is a security mechanism used with OAuth 2.0 to protect the authorization process.

It prevents attackers from stealing an authorization code and using it to obtain an Access Token.

PKCE is commonly used in:

- Mobile applications.
    
- Single Page Applications (SPA).
    
- Applications that cannot securely store a client secret.
    

## **1. Why do we need PKCE?**

Imagine you are logging into an application using Google.

During the OAuth authorization process:

1. Your application redirects you to Google.
    
2. Google authenticates you.
    
3. Google sends an **Authorization Code** back to your application.
    
4. Your application exchanges that code for an Access Token.
    

The problem is that an attacker might intercept the Authorization Code.

Without additional protection, the attacker could potentially exchange that code for an Access Token.

PKCE helps prevent this.

## **2. How does PKCE work?**

PKCE introduces two important values:

- `code_verifier`: A randomly generated secret string created by the application.
    
- `code_challenge`: A transformed version of the `code_verifier`.
    

The process:

1. The application generates a random `code_verifier`.
    
2. It creates a `code_challenge` by hashing the verifier using SHA-256.
    
3. It sends the `code_challenge` to the Authorization Server.
    
4. The user authenticates.
    
5. The Authorization Server returns an Authorization Code.
    
6. The application sends the Authorization Code and original `code_verifier` to the server.
    
7. The server verifies that the verifier matches the original challenge.
    
8. If they match, the server issues the tokens.
    

## **3. Visual example**

```
Application                 Authorization Server
     |                                |
     | Generate code_verifier         |
     | Generate code_challenge        |
     |                                |
     |---- Authorization Request ---->|
     |     code_challenge              |
     |                                |
     |<--- Authorization Code --------|
     |                                |
     |---- Token Request ------------>|
     |     authorization_code          |
     |     code_verifier               |
     |                                |
     |     Verify the challenge        |
     |                                |
     |<--- Access Token ---------------|
```

## **4. Important terminology**

|Term|Meaning|
|---|---|
|Authorization Code|Temporary code returned after successful authorization.|
|Code Verifier|Random secret generated by the application.|
|Code Challenge|Transformed version of the verifier.|
|SHA-256|Hashing algorithm used to generate the challenge.|
|Authorization Server|Server responsible for issuing tokens.|

## **5. What is the difference between OAuth, OIDC and PKCE?**

|Technology|Purpose|
|---|---|
|OAuth 2.0|Authorization: What can an application access?|
|OIDC|Authentication: Who is the user?|
|PKCE|Security: How can we protect the authorization code exchange?|

**In simple terms:**

- OAuth allows applications to access protected resources.
    
- OIDC allows applications to authenticate users.
    
- PKCE protects the authorization process against authorization code interception.
    

**Important:** PKCE is not a replacement for OAuth or OIDC. It is an additional security mechanism used with them.
