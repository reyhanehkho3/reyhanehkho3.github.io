**i18n** stands for **internationalization**.

In a Vue project, it usually means the system that lets your application support **multiple languages**.

The name comes from:

> **i** + 18 letters + **n** → **i18n**

because there are 18 letters between `i` and `n` in _internationalization_.

### Example

Instead of writing this directly:

```vue
<h1>Welcome</h1>
```

you define a translation key:

```vue
<h1>{{ $t('welcome') }}</h1>
```

Then you have translation files:

```javascript
// en.js
{
  welcome: "Welcome"
}
```

```javascript
// fa.js
{
  welcome: "خوش آمدید"
}
```

If the current language is English:

```text
Welcome
```

If the current language is Persian:

```text
خوش آمدید
```

### In a Vue project

You'll often see something like:

```text
src/
├── i18n/
│   ├── index.js
│   ├── messages.js
│   └── ...
│
├── views/
├── components/
└── App.vue
```

And code such as:

```javascript
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
```

Then:

```vue
<button>
  {{ t('login') }}
</button>
```

So the architecture is roughly:

```text
Vue Component
     │
     │ t('login')
     ↓
   i18n
     │
     ├── English → "Login"
     ├── Persian → "ورود"
     └── German  → "Anmelden"
```

Since your project has `frontend/src/i18n/messages.js`, **that folder is specifically related to managing the UI's translations/localization**.
